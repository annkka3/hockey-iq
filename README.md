# Hockey IQ

Тренажёр хоккейного мышления для центрального нападающего U15. Ситуация на льду оживает и замирает, и нужно решить, куда ехать или что делать с шайбой. Каждая карточка проходит в три шага: «Смотри» (подводка), «Предскажи» (что произойдёт) и «Действуй» (решение). Потом приложение проигрывает последствия, показывает лучшее решение, условия, при которых оно лучшее, и принцип.

Это отдельное приложение. У него свой репозиторий, свой проект Firebase (пока не создан), свои ключи хранения `hk_*` и свой кэш `hk-shell-*`. С языковыми приложениями оно не пересекается.

Живая версия: https://annkka3.github.io/hockey-iq/

## Что внутри

- **Сегодня и программа «Центр U15».** Недельные квоты по трекам: поддержка 25 %, чтение 25 %, оборона 20 %, атака 20 %, спецбригады 10 %. В каждой тренировке есть слот «Мои моменты». Ошибки повторяются по интервалам, в конце смены идёт «Закрепить ошибки».
- **Ситуации.** 159 карточек и 20 розыгрышей: колоды, миссии и разборы с ветвлением. После ошибки приложение даёт одну главную рекомендацию и «Ещё способы», то есть ссылки на похожие ситуации, разбор, режим броска или тренажёр.
- **Схема сверху и вид «Глазами».** Это два способа показать одно и то же состояние. Игрок стоит в одной точке на схеме и в виде глазами, по построению.
- **Бросок.** Семь режимов: угол, обыграй вратаря, королевская дорога, в движении, протяжка, заслон, добивание. Уровни «Новичок» и «Профи». Отдельно оцениваются решение, исполнение и исход, есть замедленный повтор и вкладка «Как считается».
- **Тренажёры внимания.** Плечевой осмотр, где партнёры, откуда давят, кто откроется, самый опасный, открытый игрок, память, слежение, предсказание, вбрасывание, блиц. Статистика внимания собирается по каждой попытке.
- **На льду.** Три навыка в фокусе и наблюдения на матче («да / частично / нет»).
- **Родителям** (PIN): активность, слабые принципы, застрявшие ситуации, внимание, сообщение и цель недели, редактор «Мои моменты», ревью карточек («Не так» / «У нас иначе» убирает карточку из тренировок).
- **Контрольный тест.** Три сменяющихся набора отложенных карточек, без подсказок цветом.

### Координаты и карточка

Метры: `x` от −15 (левый борт) до 15, `y` от 0 (свой торец) до 60, атака вверх. Линии ворот на 4 и 56, синие на 22,86 и 37,14.

```json
{
  "id": "u15-01", "deck": "…", "phase": "dz", "principle": "…", "track": "support", "view": "dz",
  "question": { "kind": "choice", "text": "…" },
  "us":   [{ "id": "C", "role": "C", "me": true, "x": 0.5, "y": 12.5, "face": [-0.5, -0.85], "stick": [-0.1, 11.6], "hand": "L", "action": "receive" }],
  "them": [{ "id": "o1", "role": "F", "x": 2, "y": 16 }],
  "puck": { "x": -3.4, "y": 6.2 },
  "read": { "text": "…", "options": [{ "id": "a", "label": "…", "correct": true, "explain": "…" }] },
  "options": [{ "id": "a", "label": "…", "verdict": "best", "explain": "…",
                "moves": [{ "who": "puck", "to": [0.2, 12.3], "kind": "pass" }] }],
  "why": { "text": "…", "options": [] }, "best_when": "…",
  "variants": [{ "key": "clock:shift-end", "verdicts": { "a": "best" }, "explain": { "a": "…" } }]
}
```

- `verdict`: `best` / `ok` / `risky` / `bad`. Очки: 10, 5, 3, 1; верное «Предскажи» +3, верное «Почему» +2.
- У игрока:
  - `face` — куда развёрнут корпус;
  - `stick` — точка контакта крюка;
  - `hand` — хват `L`/`R`; если не задан, назначается устойчиво по id, около 60 % левшей; у «Я» берётся из профиля;
  - `action` — явное действие, необязательно.
- Подписи амплуа: Ц, ЛН, ПН, ЛЗ, ПЗ, ВР, «Я». Крайние — **ЛН / ПН**, это решение автора. Автотест проверяет, что ЛП и ПП нигде нет.
- После правки исходников: `python3 tools/build_content.py --strict`.

### Клюшка (`js/engine/stick.js`)

Одна модель на схему и вид «Глазами»:

- **Хват закреплён за игроком.**
  - L: нижняя рука левая, верхняя правая, крюк на форхенде слева.
  - R: зеркально.
  - Поворот корпуса, камеры, бекхенд и зеркалирование картинки хват не меняют.
- **Отдельные точки:** торец (верхняя рука), нижняя рука, пятка, носок, нормаль рабочей стороны крюка и точка контакта с шайбой. Крюк продолжает древко в плане. Пятка не дальше настоящей длины клюшки (1,45 м), растягивать клюшку нельзя.
- **Действие** (`actionOf`), по порядку:
  - явное `action`;
  - ведение (шайба у игрока);
  - приём (только если все варианты ответа начинаются с одной передачи этому игроку, иначе поза подсказала бы ответ);
  - перекрытие (один ближайший игрок на шайбу и по одному на каждую линию паса);
  - готовность.
  Во время анимации действия меняются: пас → готовность, приём → ведение.
- **Вид «Глазами».** Картинка игрока выбирается по ракурсу, хвату, направлению и действию (`gripSprite`). Древко рисуется прямой через обе руки картинки и доводится до льда на глубине пятки из модели.

### Вид «Глазами» (`js/engine/pov.js`, `js/modules/povui.js`)

- **Камера:** на высоте 1,6 м, FOV 80°, лёгкий наклон ко льду. Позиции каждый кадр берутся из сущностей схемы.
- **Ракурсы игрока:** лицом, вполоборота лицом, боком, шаг катания, вполоборота спиной, спиной. Картинка закреплена точкой между коньками.
- **Ворота:** объёмная рама с сеткой. Они сортируются по глубине вместе с игроками.
- **Вратарь** всегда лицом к площадке. Позы: стойка, разворот к острому углу, «бабочка» при близкой шайбе.
- **Управление:** голову можно повернуть кнопками «Влево / Вправо» или пальцем. Своя клюшка держится корпусом.
- **Ответ касанием:** можно ткнуть в партнёра на сцене, если в вариантах есть пас ему.

### Бросок (`js/engine/shot.js`, `js/modules/shot.js`)

- **Геометрия (точно).** Силуэт вратаря проецируется на створ 1,83 × 1,22 м лучами из точки броска. Рама — трубы радиусом 3 см, шайба — диск радиусом 3,8 см.
- **Дуга.** Шайба летит под действием силы тяжести, без сопротивления воздуха. Угол вылета подбирается под высоту прицела. Броски до 15 см идут по льду. Встреча с вратарём и защитником считается по высоте дуги на их глубине.
- **Параметры (приближённо).** Реакция вратаря по уровню, скорость рук и щитков, разброс растёт с силой броска. Бросок в одно касание: окно 0,15 с, разброс ×1,35. Бросок после приёма: 0,18 с на обработку, разброс ×0,8.
- **Вратарь на экране.** Цельная поза (стойка, бабочка, разворот, толчок, сейв ловушкой, блином или щитком) в масштабе 300 единиц на метр. Позы сменяются плавно. Ловушка всегда на его левой руке, зеркалить позы вратаря нельзя.
- **Механика самого броска** (перенос веса, прогиб клюшки) не моделируется.

### Тренажёры и статистика внимания (`js/modules/react.js`)

- **Поведение в тренажёрах.**
  - Скрытые игроки продолжают двигаться: ответ проверяется по тому, где они сейчас.
  - «Кто откроется» учитывает перекрытые линии паса.
  - «Предсказание» включает торможение.
- **Что записывается в каждой попытке:**
  - время осмотра (до первого касания или до первого взгляда через плечо);
  - время выбора;
  - фальстарты (касания во время показа);
  - число взглядов.
- **Где видно:** сводка на экранах игрока и родителя — медианы, фальстарты и тренд за 10 серий.

### Картинки (`img/sprites/`)

Полевые игроки:
- холст 560 × 600, фигура ростом 560 единиц, опора в точке (280, 588);
- асимметричные ракурсы нарисованы смотрящими влево, вправо картинка зеркалится, и при этом левая рука становится правой;
- точки рук каждой картинки — в `GRIPS` в `sprites.js`;
- красные версии получаются перекраской синих (`tools`-скрипт обработки хранится вне репозитория). Полевых зеркалить можно, клюшку рисует код.

Вратарь:
- кадр 640 × 600, 300 единиц на метр;
- руки в каждой позе — в `GOALIE_HANDS`.

Новая картинка добавляется так:
1. Привести её к тому же холсту и опоре.
2. Отметить руки в `sprites.js`.
3. Добавить файл в `CORE` в `sw.js` и поднять `VERSION`.

## Автотесты

```
npm install          # ставит playwright (dev)
npx playwright install chromium
npm test             # юнит + сквозные
npm run test:unit    # только юнит, без браузера
```

- `tests/unit.mjs` — модели без браузера:
  - хват и роли рук, бекхенд, длина клюшки;
  - дуга броска, рама, пустые ворота, сейв в корпус, рост силуэта при выходе;
  - контент: у каждой карточки и контекста есть лучший ответ, игроки на площадке, нет ЛП и ПП.
- `tests/e2e.mjs` — приложение на собственном статическом сервере в Chromium:
  - все карточки с «Предскажи» проходятся до результата;
  - вид «Глазами» с касанием и поворотом;
  - все режимы броска в «Новичке» и «Профи»;
  - все тренажёры.

  Любая ошибка страницы роняет тест. Если playwright стоит не в проекте, путь можно указать через `PLAYWRIGHT=/путь/к/playwright/index.mjs`.

## Облако (когда понадобится второе устройство или командная версия)

1. [console.firebase.google.com](https://console.firebase.google.com) → новый проект, например `hockey-iq`. **Не** проект языковых приложений.
2. Authentication → Sign-in method → «Email/Password».
3. Firestore Database → создать (europe-west) → Rules → вставить `firestore.rules` → Publish.
4. Project settings → Web app → скопировать `firebaseConfig` в `config.js` вместо `firebase: null`.
5. Authentication → Settings → Authorized domains → добавить `annkka3.github.io`.

## Публикация

GitHub Pages из ветки `main`. При изменении файлов оболочки поднять `VERSION` в `sw.js`. Иначе телефон покажет старую версию, пока приложение не перезапустят дважды.
